# Web 平台演进规划

本次先交付独立可运行的 CLI 和离线报告，不建立空壳 Web 应用，不引入前端框架、数据库或任务队列。

## 当前可复用边界

| 模块 | 职责 | 后续 Web 如何调用 |
| --- | --- | --- |
| client | 请求第三方 lookup | 由服务端调用，浏览器不持有代理凭据 |
| profiles / scenarios | 档位、场景、请求构造与重放校验 | 提供选择、编辑、预检界面 |
| runner | 执行实验、复用缓存、处理失败 | 逐步拆出参数化任务接口与进度回调 |
| storage | 快照、响应、进度 | 保留 session v1 兼容读取，按需要增加存储适配器 |
| analysis | 概率、EV、结构和风格判定 | CLI 与 Web 共享纯分析能力 |
| reports | 派生数据和静态报告 | 同一缓存生成离线 HTML 或供交互页展示 |

## 建议下一步

1. 将 CLI 参数解析与 runner 的任务参数进一步分离，提供创建、查询、取消、续跑接口。
2. 增加 `src/server/`，先做本机单用户调试入口，提供受控的实验列表和进度事件。
3. 增加 `src/web/`，支持场景编辑、合法性预检、单次 lookup 调试、风格对照和历史实验浏览。
4. 为编辑后的场景及报告保存版本和来源，保持原始请求/响应不可变；取消或页面刷新不触发隐式重发。
5. 确有多人协作或大量任务需求后，再评估鉴权、并发限额、队列和数据库。

任何报告样式调整都应读取缓存，不把“重绘页面”与“发起求解”绑定为同一个操作。
