# Web 工具使用与实现说明

## 启动和连接

在本仓库执行 `bun run web`，Bun 自动加载本项目 `.env`。默认地址为 `http://127.0.0.1:3210`，可设置 `WEB_PORT` 后重启。没有外部工作区的文件、配置或依赖引用。

大模型与 solver 是两个独立服务。DeepSeek / Gemini 理解玩家描述、生成路线、分析实测结果；服务商、模型、根地址、temperature、输出上限和超时均可编辑。solver 沿用 `AI_SERVICE_URL`、`AI_USE_PROXY`、`AI_PROXY_URL`、`AI_REQUEST_TIMEOUT_MS`，调用 `/lookup?services=RL`，只从本项目环境读取配置。

生成场景、风格推荐和结论分析使用后台任务：提交后立即返回调用 ID，页面查询任务状态，不让浏览器长期等待同一个生成 HTTP 请求。默认模型超时为 600 秒，可在界面按秒设置 1..900 秒；旧配置保留原值，需要时手动调整。快速测试仍最多 60 秒。

DeepSeek 业务调用采用流式响应，展示接收状态、输出字符数与思考字符数，不展示原始思考内容。每秒至多落盘一次接收快照，完成后保存完整响应。连接、读取正文、流式中断和超时会区分记录，失败不自动重试。Gemini 业务调用也在后台执行，未返回完整响应时仅显示等待/接收状态。

刷新页面通过本机保存的调用 ID 恢复查询，不会重新生成；服务重启则将尚未结束的任务标为中断，保留记录与流式片段。生成期间修改草稿后，不自动覆盖新草稿，提供“应用生成结果 / 保留当前草稿”的选择。

DeepSeek 默认根地址 `https://api.deepseek.com`，适配 Chat Completions JSON 模式；Gemini 默认根地址 `https://generativelanguage.googleapis.com/v1beta`，适配原生 generateContent JSON 模式。模型名称由用户根据账号可用性填写。连接参考：[DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode/)、[Gemini API](https://ai.google.dev/api/generate-content)。

可使用服务端环境变量 `DEEPSEEK_API_KEY` / `GEMINI_API_KEY`，或在 Web 设置中填写。Web 保存的对应服务商密钥优先于环境变量；页面只返回是否已配置，留空保留已有密钥。API 根地址不允许内嵌凭据。模型密钥不用于 solver，solver 的代理配置也不会自动应用到大模型请求。

### 模型列表、快速测试与图片输入

模型设置提供内置参考列表、服务端刷新和手动 ID 输入。2026-11-25 核对的 DeepSeek 当前模型包括 `deepseek-flash`（V4.1 Flash，支持图片）和 `deepseek-v4-pro`（Pro，当前仅文本），保留旧 Flash / Vision 别名与旧 Chat / Reasoner 配置选项，不保证旧名称仍可用。Gemini 提供多模态模型和旧配置选项。实际权限与版本以当前账号返回及测试结果为准。参考：[DeepSeek 模型信息](https://api-docs.deepseek.com/quick_start/pricing/)、[DeepSeek Vision](https://api-docs.deepseek.com/guides/vision/)、[Gemini 模型信息](https://ai.google.dev/gemini-api/docs/models)。

“从服务端刷新模型”使用当前表单根地址和密钥调用 `/models`。Gemini 自动跟随分页，只显示声明支持 `generateContent` 的选项。图片能力优先采用服务端的输入模态元数据；未声明且没有已知文档信息时标注待确认，不仅靠名称推断。

“快速测试大模型”使用当前表单配置，无需先保存；新输入的密钥不会因此保存。可编辑测试内容并附图片，返回回复、请求/实际返回模型、耗时、token 用量和调用记录。测试执行一次模型请求，不创建实验、不调用 solver；输出最多 2048 token，超时最多 60 秒。现代 DeepSeek 的快速测试关闭思考以缩短等待；场景生成提供思考开关，其他业务调用沿用所选模型的默认行为。失败反馈不会回显上游 HTTP 错误正文或凭据。

图片输入用于快速测试、玩家推荐、场景生成和单条路线重生。支持 PNG、JPEG、WebP，最多 4 张，每张 2 MiB，总计 6 MiB；服务端检查 Base64、文件头、类型与大小。图片选择后仅本机预览，点击 AI 执行才随文本发送；提示词预览不调用上游。已知仅文本的模型会在请求前拒绝图片。未知或自定义模型的图片与 JSON 支持由实际 API 决定，可先快速测试。这里支持图片理解，不提供图像生成、语音或视频接口。

图片原文随模型输入快照保存在本机调用记录中；分享记录前应核对其中的图片内容。此次变更不覆盖已有模型配置或密钥。更新代码后需重启 Web 服务并刷新页面。

## 玩家与档位

实验工作台和玩家配置库标题旁的“指标说明”打开同一个通用 HUD 帮助弹窗，介绍 VPIP、PFR、AF、WTSD 的含义、公式、排除项和组合示例，并区分长期统计、catalog 档位与单个场景的动作概率。弹窗支持关闭按钮、Esc 关闭、键盘焦点返回入口与窄屏阅读；查看不会修改当前表单或调用模型。

catalog 完整按盲注结构、人数范围、翻前/翻后展示，包含 profileName、VPIP、PFR、AF、WTSD。保留上游字段名；档位名称数字不保证等于实测值。

首版执行规则固定为 6 人、100BB、无前注无抓注，只选择 `2-0 / 4-6p` 对应阶段的档位。其他桌型显示“仅预览”。大模型推荐必须通过档位存在性与阶段检查；任意自定义参数暂不发送给 solver。

松弱、紧凶、GTO 是初始预设，可修改或新增最多 8 个玩家配置。每个玩家分别保存翻前和翻后档位。玩家 ID 用于结果对齐，GTO 响应匹配按实际 `profileName=gto` 判断，允许自定义 ID 的 GTO 组合。

## 场景设计

### 场景库与快速复用

侧栏“场景库”、实验工作台“从场景库选用”和分批面板“打开场景库”进入同一个页面。场景生成结果按 JSON 持久化在本机 `artifacts/workbench/`，不是只存在于浏览器缓存：分批任务在 `generations/<id>/generation.json`，早期单次生成和单条重生结果在 `calls/<id>/result.json`，实验路线快照在 `runs/<id>/experiment.json` 或 session v1 的 `session.json`。

场景库只读汇集这些快照，逐条重新校验，相同 Hero、底牌、街道和行动线合并展示并保留来源。读取不到或校验失败的记录单独提示，不阻断其他合法路线。不会读取密钥或完整模型响应，也不改变原始缓存格式。尚未保存的手工编辑草稿不自动入库，保存实验后即可收录。

支持按街道、来源任务及场景文字/编号/底牌/行动线搜索，展开预览路线与保存来源，跨页勾选，整组筛选后快速选择。可“替换工作台路线”或“追加到工作台”，每次最多 100 条；追加会跳过重复路线，跨来源同编号的不同路线自动改为唯一编号。复用后返回新建实验，保留当前玩家、重复次数及其他配置，不自动执行 solver。浏览器缓存清理不会删除服务端已保存的场景；新生成结果可点击“刷新场景库”读取。

单次实验 1..100 条路线，每组重复 1..10 次。solver 请求数 = 场景数 × 玩家数 × 重复次数。默认 CLI 仍是原 100 条；Web 默认使用 S01..S03 方便预览。

场景可以由大模型按数量与描述生成，也可以使用已有路线。支持逐条编辑、单条重新生成、删除和批量 JSON 导入。每次修改后需要重新校验；保存实验和发起求解前都会再次验证。

固定 BTN=0、SB=1、BB=2、UTG=3、HJ=4、CO=5，100 筹码为 1BB。路线编码：`f` 弃牌、`c` 跟注、`x` 过牌、`r` 加注到、`b` 下注、`@` 公共牌，金额为 BB。重放检查顺序、最小加注、筹码、公共牌、重复牌和 Hero 决策点，历史不支持 all-in。重复 ID、相同底牌与行动线都会拒绝，不进入 solver。单次严格生成要求数量完全一致；分批生成允许保留已通过校验的临时结果，并明确标记尚未完成数量。

自然语言要求由模型理解，重放器只证明历史合法，不证明模型完整覆盖所有语义要求；执行前需要阅读设计目的和路线预览。输出不合法或截断时保留调用记录，可查看原始结果并修改提示词或减少数量，没有隐式付费重试。

### 分批生成与临时结果

“AI 分批生成场景”默认每批 3 条、并发 2 批，可设置每批 1..5 条、并发 1..3 批。每个批次单独留存完整提示词、实际模型设置、原始响应、诊断和逐条校验结果。一批失败不阻断其他批次；成功路线立即成为本机临时结果，不等待整个任务结束。

当前 DeepSeek Flash / V4 场景生成默认显式关闭思考，可在场景设计中开启。Gemini 和旧模型沿用其接口行为。DeepSeek 的思考可能消耗输出额度；错误诊断区分输出上限、思考耗尽额度、拦截、连接中断和超时，避免仅显示笼统的“未返回完整内容”。参考：[DeepSeek 思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)。玩家推荐、结论分析沿用模型默认行为；单条场景重生也默认关闭现代 DeepSeek 的思考。

截断或连接中断时，只恢复 JSON 数组中已经完整返回的对象，逐条合法性重放校验后保存；不补写不完整对象。批内非法路线、跨批重复及不符合街道配额的条目独立拒绝，不清空同批其他合法结果。场景 ID 由批次目标统一分配，避免模型跨批重复编号。

街道配额可选择翻前/翻后均分、全部翻前或全部翻后。默认按描述，仅自动识别明确的“翻前翻后各 N 条”且合计等于总量的要求；其余自然语言约束仍需人工复核。配额在逐条校验时强制执行。

“使用已生成 N 条临时结果”将当前已校验结果替换到路线草稿，可独立编辑、校验和保存实验；仍须显式执行 solver。总目标与实际已完成数量始终分开展示，不把部分结果标为全部完成。“补跑本批剩余”只补该批缺失槽位；“继续/补齐未完成批次”只补未完成数量，成功槽位不重新请求。补跑采用当前模型、提示词及思考设置，每次尝试独立保存快照。

“暂停后续批次”让当前请求完成并保存结果，不再启动后续批次。浏览器刷新恢复状态查询；服务重启后在“查看已保存任务”恢复并显式续跑，不自动重发。任务存放于 `artifacts/workbench/generations/<id>/generation.json`，原始调用仍在 `calls/<call-id>/`。调用记录中的“定位失败原因”也支持读取旧调用的结束原因和 token 用量。

## 执行、续跑与报告

保存实验只创建请求计划，不执行求解。计划保存后不可变；修改玩家或路线需要复制为新实验。历史实验不随配置库变化。

执行时共用 CLI 缓存执行器。响应先原子保存，再更新进度；失败也保留。继续执行只请求缺失项，显式“重试失败项”会重试失败缓存，成功缓存始终复用。被替换的失败响应另存带 UUID 的归档文件。服务器重启后将未结束的实验显示为中断，可以显式续跑。页面刷新不会启动求解。

横向结果包含平均动作概率、尺寸、EV、逐次推荐、重复差异、实际档位和模型来源；基线差异按完整动作键对齐。优先以同时使用翻前/翻后 GTO 档位的玩家为基线，否则使用第一个玩家。

“结果与分析”顶部的总体结论展示场景及街道分布、请求成功/失败/未完成数量、方向判定分布、整体判断、需复核场景入口和本次玩家档位快照。此区由本机结果自动汇总，打开即显示，不调用大模型；下方大模型结论仍是独立分析。仅原始三风格及对应预设档位应用既定方向规则，自定义组合展示完整且来源一致的可比场景数。失败、未完成和来源变化不会当作符合预期。导出 HTML 共用此展示，筛选不会改变整体统计。

缺失或失败不补零概率；动作缺失只在有效结果的概率对齐中按零处理，EV 不补零。自定义玩家不套用固定三风格判定。候选动作金额按接口返回值展示，实际待跟金额以路线校验字段为准。EV 保留原接口单位。

结果页的“汇总对照表”按玩家展示彩色概率条、四类动作概率与逐次实际推荐，支持搜索及街道、位置、类型、结论筛选。点击场景编号进入明细；完整动作表默认展开，不同下注或加注尺寸分别列出平均概率、EV 和相对基线的概率差。具体动作概率保留六位小数，悬停可查看更多精度。

每个玩家卡片提供“查看第 N 次原始响应”。点击后在本页展开对应本机缓存，展示 amount 原值及 BB 换算、pot_size、seat_no、hand_strategy、hand_ev 和完整响应 JSON；也可展开完整请求、诊断和缓存记录。此操作不调用第三方。

结果页提供 HTML，可另存或打印，与 Web 共用汇总表和动作明细。HTML 内嵌全部已有原始缓存、派生结果、诊断和最后一次成功的大模型结论，离线仍可筛选与展开原始响应。调整报告只点击“离线重建报告”，不会重发 solver 请求。

## 提示词与分析追溯

风格推荐、场景生成、结论分析分别拥有系统提示词和输入模板，支持编辑、未保存预览、保存新版本、历史载入及恢复默认。业务调用使用已保存版本；固定输出格式与桌型约束始终追加，服务端独立校验输出。

- 风格推荐变量：`{{input}}`、`{{catalog}}`。
- 场景生成变量：`{{input}}`、`{{examples}}`。
- 结论分析变量：`{{input}}`、`{{results}}`。

每次模型调用保存创建时间、完整提示词、模板版本、模型配置、原始响应、用量和解析结果。后台任务另存 job.json（阶段、耗时、接收进度和终态）。成功 HTTP 响应即使内容截断或业务校验失败也保存原文；流式中断保留已接收片段并标为 incomplete。HTTP 错误只记录状态，避免错误正文回显凭据。调用记录按步骤独立查看和重跑。

分析输入来自已保存 solver 结果，包含全部场景横向数据和逐次基线差异。模型必须返回总体结论、全部场景结论和限制；拒绝遗漏、未知或重复场景 ID。同一实验求解和分析互斥，分析不改变 solver 响应。失败分析保留记录，旧成功结论继续可用。每份分析绑定横向结果指纹；重试更新结果后，旧分析标记过期并保留在历史版本中，需要重新分析。

单次提示词输入限制为 600,000 字符，超出时在请求前拒绝。大批量、多玩家、多重复实验可能需要拆成较小实验，后续可增加分批分析。模型分析中的数值与因果表述仍应结合原始概率和来源复核。

## 数据目录

```text
artifacts/workbench/
  settings.json                   模型设置、玩家配置、当前提示词版本
  secrets.json                    可选的本机服务端密钥，不分享
  prompts/<version>/version.json  历史提示词
  calls/<call-id>/                request / response / result.json
  runs/<run-id>/                  session v1、experiment.json、逐次响应、进度
                                  validation.json、horizontal.json、report.html
  public/                        旧版浏览器构建缓存（新版不再读取）
```

旧 CLI 的 `artifacts/runs/` 不迁移、不清理，布局和 `--render-only` 保持兼容。Web 只读取受控的实验与调用记录路径，密钥文件不通过静态文件服务公开；服务绑定本机，并拒绝跨来源写请求。

Web 服务在启动时将浏览器代码构建为进程内快照，不再从共享 `public/app.js` 读取，避免另一次启动或端口占用导致不同服务混用前端版本。新前端兼容旧 bootstrap 缺少模型列表字段的情况，并提示重启旧服务；异常页面缺少表单时仍允许切换导航。

## 验证

执行 `bun run check:type`、`bun run lint`、`bun run test`、`bun run format:check`。新增测试使用本机临时 HTTP 服务验证两类模型适配、非法输出拒绝、提示词版本与快照、自定义 GTO、失败缓存和续跑、横向对比、结论分析、HTML 转义与跨来源保护。普通测试不需要真实服务或密钥。
