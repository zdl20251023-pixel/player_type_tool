# 迁移来源与兼容性

## 直接复制的内容

使用本机文件复制命令从原项目工作树复制 20 个代码/文档/配置文件，复制后逐一核对 SHA-256。复制时的路径映射及原始哈希见 `migration-copy-manifest.json`；其中记录的是首次复制校验值，后续必要的导入路径和入口适配会改变部分目标文件哈希。

完整复制正式实验 `95071a04-37d2-4858-9b00-ea057adaca09`，共 609 个文件，包含 600 份原始请求/响应、快照、进度和报告。复制时所有文件 SHA-256 均一致。缓存位于本地 `artifacts/runs/`，不入 Git。

没有复制原项目 node_modules、真实 .env、凭据、数据库/Redis 配置或业务玩家钩子。

## 必要适配

- 依据本仓库职责目录机械调整 import 路径；抽取原有实验类型、风格配置、统计判定函数和 CLI 入口，不重写场景数据、比较算法或 HTML 模板。
- 客户端保留原 HTTP 实现的请求头、路径、代理路由、超时及原样响应方式；删除后端配置表和无关 strategy_grid 初始化依赖。
- 超时由 `AI_REQUEST_TIMEOUT_MS` 读取，默认 3000ms；显式关闭代理时不自动使用系统代理。HTTP 请求行为由本机临时服务集成测试验证。
- 只保留独立 lookup 请求/响应契约，去掉业务 ErrCode、玩家钩子及 strategy_grid 类型依赖。
- UTC 时间快照改用标准 `Date.toISOString()`；报告仍以 Asia/Shanghai 显示，不依赖原时间包装器。
- 增加自己的 package.json、bun.lock、类型/格式/lint 配置和环境模板，依赖版本沿用迁移时已验证版本。
- 三种风格文档中的指标由复制后的 catalog 确定性提取，不重新生成指标或重新请求第三方。

## 兼容策略

首轮继续使用 session v1；每个实验目录内部保持原平铺布局，保留原请求 ID、快照和原始响应。只有实验父目录从原工具的本地目录变为本仓库 `artifacts/runs/`，不改请求内容或缓存版本。

旧缓存的 `--render-only` 和完整缓存 `--resume` 均可直接运行；没有缺失项时不要求 AI 服务地址，不加载 HTTP 客户端，不发新请求。HTML 原始 JSON 链接仍可用。项目不通过 import、符号链接或安装时脚本访问原仓库。

原后端项目保留，未做清理、删除或提交。本仓库接续后续工具开发，原始参考文档中的业务调用链只作为历史信息。
