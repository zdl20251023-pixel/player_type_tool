# 实验准备页与交互

实验工作台顶部保留“新建实验 / 实验记录 / 结果与分析”。新建实验页只显示实验名称、已选玩家、已选场景和请求数量摘要；列表内部滚动，复杂操作在弹窗完成。初次进入和刷新后提供空白准备页；浏览器已有草稿通过“继续上次草稿”显式恢复，不自动加载默认玩家、代表路线或旧生成结果。

## 玩家与场景

- “添加玩家”在弹窗中搜索和筛选 75 种内置角色或个人配置，最多选 8 个；点击“加入本次实验”才更新主列表。取消不改变选择。主列表只展示已选玩家，移除只影响本次草稿。重新添加时仍可从选择弹窗找到个人配置。
- “添加场景”集中提供 AI 生成、示例路线、内置场景集、我的场景库。候选列表支持搜索、街道筛选、分页、勾选和路线预览。AI 的分批、思考、图片与提示词预览在高级设置中；生成记录和重试保留在弹窗内。
- 候选不自动成为实验输入。选择“追加”或“替换”并确认后，统一调用本机合法性重放校验，再更新草稿。追加跳过重复路线，编号冲突自动加后缀，总量最多 100 条。
- 主列表标记来源和校验状态；编辑弹窗内保存并校验后才修改当前路线，取消保留原路线。不修改来源场景或历史快照。

## 草稿和生成任务

沿用浏览器 `strategy-lab-draft-v1`，兼容旧字段并增加可选的草稿标识、UTC 保存时间、场景来源和生成任务关联。上次草稿与重置前的恢复副本保存在 `strategy-lab-previous-draft-v1`。重置不会删除本机个人配置、场景库、生成记录或实验数据。

生成任务只与明确关联的草稿展示在一起。重置后解绑前端任务跟踪，后台任务继续落盘；晚返回的旧结果不应用到新草稿。用户仍可从生成记录和场景库显式选用。普通浏览、筛选、加入候选、修改草稿不会调用大模型或 solver。

新场景默认自动分批：每批最多 3 条，同时最多执行 2 批。生成数量变化时实时更新每批条数、批次数和并发；例如 2 条为 1 批、并发 1，10 条为 3+3+3+1 四批、并发 2。生成按钮上方始终显示实际计划。手动修改每批条数或并发会进入手动模式，可恢复自动；手动值也受实际总数和批次数限制。修改只影响下一次生成，不改变进行中或历史任务。

DeepSeek 新场景默认开启思考，仍可手动关闭；思考会消耗输出额度并可能增加耗时，不支持切换的模型沿用服务商行为。浏览器旧版未区分用户意图的默认参数迁移为自动分批、思考开启；新版本中明确保存的手动选择继续保留。已落盘任务快照不迁移。

明确描述“翻前和翻后各 3 条”或“翻前 2 条、翻后 4 条”等数量时，前后端在预览和创建任务前检查其总数是否与生成数量一致；不一致时提示修改，不发送模型请求，不静默改变输入。均分描述及明确的两街道数量在按描述模式下形成对应街道配额。分批内部调用仍按各批剩余目标执行，不把整任务描述数量误当成本批数量。

## 开始、记录与结果

“开始对比”先检查名称和输入，对当前路线重放校验，保存独立的实验快照后启动 solver，切换到结果页显示进度。若保存后执行失败，保留已创建实验，可从记录继续，避免要求重新生成。

实验记录可按名称、玩家、ID 搜索和状态筛选。结果页分为“总体结论 / 场景对比 / AI 分析 / 原始数据”，保持当前实验名称和 ID 可见；原始响应继续按场景明细懒加载。HTML 报告导出、重试失败项、离线重建、复制为新实验等入口保留。仅切换界面不会重新请求第三方。
